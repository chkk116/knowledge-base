# 运行时实测结果（MVP）

引擎：RapidOCR (ONNX) + ONNX Runtime，CPU。测试集：合成中文 27 张 / 5 类难度（自带标准答案）。
指标：字符级准确率 = 1 - CER（去空白归一化）。

## 对比：裸 RapidOCR vs 本运行时（版面重排）

| 难度类别 | 裸 RapidOCR | 运行时(版面重排) | 变化 |
|---|---|---|---|
| 干净单行 | 92.9% | 92.9% | 0 |
| 中英文+数字混排 | 74.6% | 74.6% | 0 |
| 多行段落 | 97.3% | 97.3% | 0 |
| 扫描噪声 | 98.4% | 98.4% | 0 |
| 双栏 | 52.7% | 94.6% | +41.9pt |
| 整体 | 83.0% | 91.8% | +8.8pt |

## 结论
- 版面阅读顺序修正有效：双栏 52.7% -> 94.6%，且单栏文档零回归（保守策略：仅当检测到显著竖向空隙时才重排）。
- 数字后处理对本测试集无效：混排样本错误主要是字符被整段漏掉（KB->K、¥1,299.00->129.0），当前后处理只做字母/数字混淆替换（O->0、l->1、S->5 等），无法恢复被删字符。对混淆型错误有效，覆盖面有限，属已知 scope 非 bug。
- 整体 +8.8pt，主要收益来自双栏/多栏场景（通用 OCR 最易翻车处）。

## 已知边界（下一步）
- 双栏/多栏：规则版面对简单双栏有效；三栏、嵌套、图文混排仍需版面检测模型（PP-Structure）兜底。
- 数字/金额：漏字类错误需更强识别模型或置信度校验，后处理无法根治。
- 测试集为合成小样本（27 张），正式评估需更大真实中文数据集（建议 >=500 张真实文档照片）。
